# TECH RADAR | ai.nxt
**نرصد المستقبل التقني**

منصة عربية ثابتة لمتابعة الأخبار التقنية، مع أولوية للذكاء الاصطناعي، ومشاريع GitHub، والنماذج والأوراق البحثية والإصدارات.

## ما يتضمنه المشروع
- واجهة عربية RTL، داكنة افتراضياً مع وضع فاتح، متجاوبة مع الهاتف والحاسوب.
- الأخبار، الذكاء الاصطناعي، GitHub، الإصدارات، الشركات، التقرير اليومي، المحفوظات، والإعدادات.
- جامع Node.js يعمل عبر GitHub Actions كل ساعة.
- 109 مصدراً مهيأً حالياً: RSS، مواقع رسمية، GitHub Releases/Search، Hugging Face، Hacker News، Reddit، وarXiv.
- إزالة تكرار الروابط وتشابه العناوين، وإظهار المصادر الأخرى عند الدمج.
- تصنيف محلي ومستويات أهمية؛ «عاجل» محكوم بشرط زمني وحدث حرج ومصدر رسمي أو مصدرين.
- ترجمة وتلخيص اختياريان عبر Claude API، ومفتاحه محفوظ في GitHub Secrets وليس في الواجهة.
- حالات المصادر وأخطاء الجلب تظهر في الإعدادات.

## النشر على GitHub
1. أنشئ مستودعاً جديداً، وارفع **محتويات** هذا المجلد إلى جذر الفرع `main` (لا ترفع ملف ZIP نفسه).
2. افتح `Settings → Pages`، واختر `Deploy from a branch` ثم `main` و`/(root)`، واحفظ.
3. افتح `Settings → Actions → General`، وتأكد من السماح للـ Actions بإنشاء التغييرات. سير العمل يحدد `contents: write` بالفعل.
4. افتح `Actions → تحديث الرادار التقني` ثم `Run workflow` لتشغيل أول مزامنة يدوياً.
5. راقب سجل التشغيل. يجب أن ترى عدد المصادر الناجحة، وأخطاء المصادر الفردية، وحالة Claude. بعد نجاح التشغيل تتغير `news.json` و`seen.json` في المستودع.
6. انتظر نشر GitHub Pages، ثم افتح رابط الموقع.

## تفعيل الترجمة والتلخيص بـ Claude
هذه الخطوة اختيارية، وتستهلك رصيد API لدى Anthropic:
1. أنشئ مفتاحاً من حساب Anthropic الخاص بك.
2. في المستودع افتح `Settings → Secrets and variables → Actions → New repository secret`.
3. الاسم: `ANTHROPIC_API_KEY`، والقيمة: مفتاحك. لا تضع المفتاح في `index.html` أو `app.js` أو أي ملف عام.
4. اختيارياً أضف Repository Variable باسم `ANTHROPIC_MODEL`، وإلا يستخدم السكربت `claude-haiku-4-5-20251001`.
5. شغّل Workflow يدوياً وتحقق من ظهور حالة Claude في السجل.

## إدارة المصادر
كل المصادر في `sources.json`، ضمن مجموعات جغرافية. لكل مصدر:
- `id`: معرّف فريد ثابت.
- `name`: اسم ظاهر للمستخدم.
- `type`: نوع الموصل.
- `url` أو حقول الموصل الخاصة.
- `country`, `lang`, `cat`: البلد واللغة والتصنيف الافتراضي.
- `official`: هل هو مصدر رسمي أصلي؟
- `check: true`: لم يتم التحقق الحي من هذا المصدر ضمن مراجعة الحزمة الحالية؛ اختبره قبل الاعتماد النهائي.

بعد أي تعديل:
```bash
node scripts/validate.mjs
node --check scripts/update.mjs
node scripts/update.mjs
```

### أمثلة إضافة مصادر اجتماعية عامة
أضف الكائن داخل `sources` للمجموعة المناسبة، بعد التحقق من الحساب من موقعه الرسمي:

```json
{
  "id": "youtube-example",
  "name": "اسم القناة",
  "type": "youtube",
  "channel_id": "UC...",
  "country": "US",
  "lang": "en",
  "cat": "ai",
  "official": true,
  "check": true
}
```

```json
{
  "id": "bluesky-example",
  "name": "اسم الحساب",
  "type": "bluesky",
  "actor": "handle.bsky.social",
  "country": "US",
  "lang": "en",
  "cat": "ai",
  "official": true,
  "check": true
}
```

```json
{
  "id": "mastodon-example",
  "name": "اسم الحساب",
  "type": "mastodon",
  "instance": "mastodon.social",
  "account": "handle@mastodon.social",
  "country": "DE",
  "lang": "en",
  "cat": "ai",
  "official": false,
  "check": true
}
```

`official: true` يجعل المصدر مرجعاً رسمياً عند دمج الخبر. لا تضع `UC...` أو handle تجريبياً؛ استبدله بمعرّف حقيقي تم التحقق منه.

### الأنواع المتاحة
- `rss`: موقع أو مجلة أو مدونة أو نشرة Substack ذات RSS.
- `youtube`: يتطلب `channel_id` دقيقاً من صفحة القناة الرسمية؛ لا تخمّن المعرف.
- `reddit`: رابط RSS للمجتمع أو `sub`.
- `bluesky`: واجهة Bluesky العامة، وتتطلب `actor` موثقاً (handle).
- `mastodon`: الواجهة العامة الرسمية للخادم، وتتطلب `instance` و`account` موثقين.
- `github-releases`, `github-repos`, `hf-models`, `hf-papers`, `hn`, `arxiv`.

### الرصد الاجتماعي والقيود
- **متاح دون كشط:** RSS للمواقع والمدونات، RSS لقنوات YouTube، Reddit، Hacker News، GitHub، Hugging Face، arXiv، وواجهات Bluesky وMastodon العامة.
- **مقيّد أو مدفوع:** X يحتاج واجهة رسمية وخطة/صلاحية مناسبة ومفتاحاً محفوظاً في Secrets. لا يوجد تكامل X مفعّل في هذه الحزمة.
- **حسابات تملكها أو تديرها فقط:** LinkedIn وInstagram وFacebook عبر واجهاتها الرسمية وصلاحيات الحسابات المناسبة. لا يوجد رصد عام واسع لهذه المنصات في الحزمة.
- **ممنوع:** كشط الصفحات أو تجاوز تسجيل الدخول والقيود أو الاعتماد على واجهات غير رسمية متقلبة.
- البديل العملي لحسابات الشركات والمشاهير: متابعة مدوناتهم الرسمية، قنوات YouTube، نشراتهم، ومصادرهم العامة على Bluesky أو Mastodon. أضف أي حساب بعد التحقق من معرّفه ورابطه.

## ما لا تدّعيه هذه النسخة
- لم يتم إجراء اختبار حي شامل لكل 109 مصدر؛ وضعت `check: true` عليها جميعاً حتى لا تُفهم على أنها اختُبرت.
- لا يمكن ضمان أن كل مصدر RSS سيبقى متاحاً؛ قد تتغير الخلاصات أو تحجب الطلبات أو تتوقف مؤقتاً. سجل Actions هو مرجع التشخيص.
- لا يوجد رصد شامل لـ X أو LinkedIn أو Instagram أو Facebook.
- تنبيهات المتصفح الفورية/البريد/Telegram غير مفعّلة في هذه النسخة؛ الوسم «عاجل» يظهر داخل الأخبار فقط.
- لا توجد قاعدة بيانات مركزية أو لوحة إدارة سحابية؛ الإعدادات المحلية في المتصفح، ومصادر الرصد تُدار عبر `sources.json`.
- لا تُعد الواجهة مصدر الأخبار؛ الرابط الأصلي وتاريخ النشر هما مرجع التحقق.

## تشخيص عدم ظهور أخبار جديدة
تحقق بالترتيب:
1. `Actions → آخر تشغيل`، واقرأ عدد المصادر الناجحة وأسماء المصادر الفاشلة.
2. تأكد أن `.github/workflows/update.yml` موجود في المستودع.
3. تأكد أن صلاحية Workflow هي `contents: write`.
4. تأكد أن `news.json` يتغير بعد التشغيل.
5. إذا فشلت كل المصادر، لا يستبدل السكربت آخر نسخة سليمة من البيانات.
